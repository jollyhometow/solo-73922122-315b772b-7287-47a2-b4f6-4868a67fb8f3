# 植被调查离线修订合并平台

数据员把外业队的离线修订 CSV 并回当前记录库，供物种分布分析入库。
FastAPI + SQLite 实现，三方向（基线 / 修订 / 当前）逐字段合并，冲突人工裁决，整批事务化应用。

## 快速启动（Docker Compose）

```bash
docker compose up --build
```

浏览器打开 **http://localhost:8000** 即可操作。SQLite 数据持久化在名为 `survey-data` 的卷中；
首次启动自动载入 `data/initial_records.csv` 的 12 条初始记录。

本地开发（可选）：

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload   # http://localhost:8000
```

## 数据格式

记录 = 唯一 ID + 样方 + 物种 + 非负整数株数。CSV 固定表头：

```csv
id,quadrat,species,count
R001,Q1,羊草,12
```

## 使用流程（网页四步）

1. **当前记录**：首页表格直接改值/删除/新增；`导出当前 CSV` 可随时下载。
2. **保存基线并导出**：点按钮把当前记录整体存为基线，并下载对应 CSV 交给外业队离线修订。
3. **上传修订**：选择该修订所基于的基线，上传外业队改完的 CSV。
   - 修订文件中**缺行 = 删除**该记录；**新 ID = 新增**。
   - 系统逐字段比较基线、修订、当前三方，生成合并预览。
4. **预览与确认**：
   - 不同字段各改各的 → 自动合并；双方改成相同值 → 只留一份；
   - 双方同字段改不同值、同 ID 新增内容不同、删除与修改相遇 → 展示三方值，逐项人工选择；
   - 全部裁决后一键**整批确认**，只应用离线改动。

## 合并规则

| 情形 | 结果 |
|---|---|
| 仅修订改了某字段 | 自动采用修订值 |
| 仅当前改了某字段 | 自动保留当前值 |
| 双方改成相同值 | 自动保留一份 |
| 双方同字段改不同值 | 冲突，人工选修订值或当前值 |
| 修订缺行（删除）且当前未改 | 自动删除 |
| 修订删除 vs 当前已修改 | 冲突：删除 或 保留当前 |
| 修订修改 vs 当前已删除 | 冲突：按修订恢复 或 保持删除 |
| 双方各自新增同 ID 同内容 | 只留一份 |
| 双方各自新增同 ID 不同内容 | 冲突：二选一 |

## 过期保护与事务性

- 预览生成时对**计划触及的记录**拍快照；确认时在同一写事务里重新读取这些记录的
  **提交前实际值**并核对。拟改记录在预览后又被修改或删除 → **拒绝旧预览**（本次不写
  任何记录或来源），按最新当前记录自动重新比较；**无关记录的变化不影响确认**。
- 整批应用（记录变更 + 来源事件 + 预览状态）在单个事务中执行，任何失败整体回滚，
  **当前数据与来源链都不变**。
- 被放弃或未确认的预览**不会写入任何“已应用”来源**；只有确认成功才留下离线修订事件。
- 并发确认同一预览时只有一次生效，其余按“已处理”返回；并发维护与确认在
  `BEGIN IMMEDIATE` 下串行，来源链始终按事务内读到的提交前值衔接。

## 字段来源追溯

每条记录、每个字段都能查到“当前值来自哪次修订/维护”：

- **来源链**：`provenance_chains` 按记录世代保存；`provenance_events` 每次**实际改值**
  只记录真正变动的字段，保存改前值、改后值、改前来源事件号，以及来源类型。
- **人工维护** vs **离线修订**：离线修订事件关联**基线号、预览号、修订原值**；
  发生冲突时还记录**冲突选择**（采用修订 / 保留当前）。人工修改只有人工事件。
- **未变字段沿用原来源**：合并只更新实际变化的字段，其他字段来源不变；
  **同值合并**（双方改成相同值）不产生新事件、不改写来源。
- **追溯起点**：启用追溯时已存在的数据统一标为“追溯起点”，不推测更早的历史。
- **删除与重建**：删除事件保留整条旧链（含删除前各字段值），同 ID 重建会**另起一条
  新链**，两代历史都可查。
- **一致性**：来源查询与当前值在同一只读快照中读取，不会出现“值已变、来源还是旧”的
  半更新画面；写操作在 `BEGIN IMMEDIATE` 事务中先读提交前值再写事件，并发维护/合并/
  查询时来源链按实际提交前值衔接。数据持久化在 SQLite 卷中，重启后保留。

网页入口：

| 页面 | 内容 |
|---|---|
| `/provenance` | 所有当前记录各字段来源总览；按 ID 搜索（含已删记录） |
| `/provenance/{id}` | 单条记录当前字段来源 + 沿链历次变化（改前/改后值、关联基线/预览） |
| `/deleted` | 已删除记录列表（保留旧链，可查看删除时的值） |
| `/deleted/{id}` | 已删记录的全部世代链（含同 ID 重建） |

## 交叉修订演示样例

`samples/` 下有两队基于初始数据的离线修订，可直接在网页上传演示：

```text
1. 首页点「保存当前记录为基线并导出 CSV」→ 得到基线 #1
2. 在当前记录里把 R003 株数改为 7、R009 株数改为 8（模拟库内同期改动）
3. 上传 samples/team_a_revision.csv（选基线 #1）
   → 7 项自动合并（改 R002/R004/R005/R010、删 R008、增 R101/R102），无冲突，直接确认
4. 上传 samples/team_b_revision.csv（仍选基线 #1）
   → 自动合并：R005 物种改扁穗冰草（与 A 的株数改动字段级合并）、R007 株数、新增 R201
   → 冲突：R002 双方改不同株数；R003 队B删除 vs 当前已改；R102 双方新增内容不同
5. 先别确认：回首页把 R007 株数改为 20，再回预览点确认
   → 旧预览被拒绝并自动重新比较（R007 变成新冲突）；R009 等无关改动不阻碍确认
6. 裁决全部冲突后确认 → 整批应用（记录与来源一起提交）
7. 打开 `/provenance` 查看各字段来源；例如 `/provenance/R005` 可见：
   株数来自 A 队修订、物种来自 B 队修订，各自关联基线 #1、预览号与修订原值
8. 打开 `/deleted` 可见 R008 的删除链；若之后新增同 ID，会另起新链供对照
```

## 测试

```bash
python3 -m unittest tests.test_provenance -v
```

覆盖：追溯起点、人工改值的改前/改后值与前一来源、未变保存不写来源、同值合并不改写来源、
离线合并的基线/预览/修订原值关联、过期预览拒绝且不写来源、放弃预览不写来源、
删除保留旧链与同 ID 重建新链、批量应用失败整体回滚。

## 项目结构

```text
app/
  main.py        FastAPI 路由：记录维护、基线、上传、预览、确认、来源查询
  merge.py       三方向逐字段合并与冲突裁决合成（含逐字段来源标记）
  csvio.py       修订 CSV 解析（校验非负整数株数等）与导出
  db.py          SQLite 访问层；来源链表与同事务应用
  templates/     页面模板
tests/          来源链行为测试
data/initial_records.csv   初始数据（首次启动自动载入）
samples/                   两队交叉修订样例
Dockerfile / docker-compose.yml
```
